# Лид-сканер для Telegram

Сервис находит людей и проекты, которым нужна аналитика для Telegram-ботов и
мини-аппов, оценивает их через Claude и присылает оператору карточку с
персональным черновиком. **Сообщение уходит только после нажатия «Отправить».**

```
Telegram-чаты (Telethon) ─┐
Telegram Ads Spy (API)    ├─► candidates ─► ключевые слова ─► дедупликация ─► Claude (JSON)
hh.ru (API), фриланс RSS  │    (в БД)        keywords.yaml      30 дней           score, сегмент,
topapps / Apps Center ... ┘                                                     черновик
                                                                                   │
            ┌──────────── hot сразу / warm пачкой раз в 2 ч ◄──────────────────────┘
            ▼
     Бот оператора: Отправить · Править · Пропустить · Позже
            │ (нажатие)
            ▼
     Очередь отправки → лимиты, интервалы, стоп по FloodWait → личка или ответ в чате
```

## Что внутри

| Файл | Что делает |
|---|---|
| `leadscanner/telegram_account.py` | Рабочий аккаунт: слушает новые сообщения в чатах, где он уже состоит; ловит ответы лидов; отправляет |
| `leadscanner/keyword_filter.py` | Ступень 1: корни из `keywords.yaml`, без учёта регистра и ё/е, минус-слова, минимум 6 слов |
| `leadscanner/llm.py` | Ступень 2: Claude API со строгой JSON-схемой ответа; черновик ≤450 знаков, ссылки вычищаются |
| `leadscanner/pipeline.py` | Конвейер. Кандидаты сначала пишутся в БД — перезапуск ничего не теряет |
| `leadscanner/operator_bot.py`, `cards.py` | Бот оператора (aiogram 3): карточки, кнопки, команды |
| `leadscanner/sender.py` | Отправка: дневной лимит, интервал + разброс, стоп на 24 ч, проверка похожести >80% |
| `leadscanner/replies.py` | Ответы лидов → `replied`; «не интересно / не пишите» → `lost` + `do_not_contact` навсегда |
| `leadscanner/sources/` | Telegram Ads Spy, hh.ru, фриланс-RSS, страницы каталогов; robots.txt и 1 запрос в 2–3 с на домен |
| `leadscanner/scheduler.py` | Пачки warm, напоминания, касания, каталоги, недельный отчёт, очистка, Sheets |
| `leadscanner/db.py` | SQLite: `leads`, `messages`, `sources`, `skips` + служебные таблицы |
| `config/*.yaml`, `config/prompt.md` | Источники, лимиты, словари, промпт, сценарий касаний. **Меняются без перезапуска** |

## Запуск

**Быстрый способ — на VPS одной командой:**
```bash
git clone -b claude/kind-gauss-j60ybc https://github.com/egorvlasov811-bot/-.git leads
cd leads/leadscanner && bash deploy.sh
```
`deploy.sh` ставит Docker (если его нет) и спрашивает ключи. Затем ждёт ваш `/start`
боту, чтобы узнать id чата, входит в рабочий аккаунт по коду из Telegram и запускает сервис.
Повторный запуск безопасен. Ниже те же шаги вручную.

1. **Аккаунт.** Отдельный аккаунт с реальным именем и аватаром, прогретый 2–3 недели
   обычным использованием. Вступите в нужные 30–50 чатов вручную.
2. **Ключи.** `cp .env.example .env` и заполните:
   - `TG_API_ID`, `TG_API_HASH` — на my.telegram.org;
   - `BOT_TOKEN` — у @BotFather;
   - `ANTHROPIC_API_KEY`;
   - `OPERATOR_CHAT_ID` — напишите боту `/start`, он покажет id чата.
3. **Сессия аккаунта** (один раз, интерактивно — придёт код в Telegram):
   ```bash
   pip install -r requirements.txt
   set -a; . ./.env; set +a
   python -m leadscanner login     # строку из вывода положите в TG_SESSION
   python -m leadscanner chats     # список чатов аккаунта → telegram.chats в settings.yaml
   ```
4. **Старт:**
   ```bash
   docker compose up -d --build     # или: python -m leadscanner run
   ```
   Папки `config/` и `data/` монтируются с хоста: словари и источники правятся
   на лету, база переживает пересборку.

## Бот оператора

Карточка:
```
🔥 HOT · 82 · media_buyer · CIS · ru
Чат: Закупка рекламы · 27.10 14:05
Автор: @username
«цитата до 300 знаков»
Боль: не понимает, какой канал закупки окупается
Ссылка на сообщение: https://t.me/chat/123

Черновик:
…
```
Кнопки: **Отправить**, **Править** (бот присылает черновик текстом, вы отвечаете
исправленной версией), **Пропустить** (не лид / не наш сегмент / уже клиент / мусор),
**Позже** (напоминание через 24 ч). У лидов из каталогов и вакансий, где нет личного
контакта, вместо «Отправить» стоит «Написал вручную» и «Указать контакт».

Команды: `/today`, `/pending`, `/followup` (касания на 2, 5 и 12 день), `/pause`,
`/report`, `/sources`, `/off <источник>`, `/on <источник>`, `/forget @username`.

## Как выполнены критерии приёмки MVP

| Критерий | Как обеспечено | Проверка |
|---|---|---|
| Карточка не позже 2 минут | Событие Telethon → БД → конвейер будится сразу; hot-лид уходит без ожидания пачки | `test_hot_lead_becomes_card` |
| ≥80% «лид / не лид» на 100 сообщениях | Промпт + JSON-схема | `scripts/eval_llm.py` на вашей выборке (см. ниже) |
| Черновик на языке автора, ссылается на его фразу | Требование в промпте; eval считает оба показателя | `scripts/eval_llm.py` |
| Ничего не уходит без «Отправить» | Очередь отправки наполняется только из обработчиков кнопок бота | `test_nothing_is_sent_without_queue`, `test_card_then_send_button_queues_and_sends` |
| Дневной лимит и стоп по FloodWait | Счётчик в БД, кнопка отвечает «лимит исчерпан»; FloodWait/PeerFlood → стоп 24 ч + уведомление | `test_daily_limit_blocks_button`, `test_flood_wait_stops_everything_for_24h` |
| Повтор автора не создаёт второго лида | Дедупликация по username/проекту за 30 дней, повтор поднимает температуру | `test_repeat_author_merges_into_one_lead` |
| Перезапуск без потерь и без повторных отправок | Кандидаты и очередь в БД; статус `sending` пишется до вызова Telegram, после падения такие сообщения → `unknown` и не повторяются | `test_candidates_survive_restart`, `test_crash_during_send_is_not_repeated` |

Тесты: `pip install -r requirements-dev.txt && pytest`.

**Проверка качества LLM.** Соберите 100 реальных сообщений из своих чатов, разметьте
`is_lead` вручную в формате `tests/data/labeled_sample.jsonl` (там 10 примеров) и запустите:
```bash
python scripts/eval_llm.py my_labeled_100.jsonl
```
Скрипт тратит по одному запросу к Claude на строку и печатает точность, долю мусора,
язык черновика и ссылку на фразу автора. Ошибки модели правьте в `config/prompt.md`.

## Защита аккаунта и данные

- 25 первых сообщений в день (настраивается 20–30), интервал 150 с + до 90 с разброса,
  лимит обнуляется в 9:00 по `timezone`.
- FloodWait, PeerFlood, UserBannedInChannel → все отправки стоп на 24 ч, оператору уведомление.
- Текст, совпадающий >80% с отправленным за сутки, не уходит — бот просит «Править».
- Ответ «не интересно / не пишите» → `lost` + `do_not_contact`, контакт в стоп-листе навсегда
  (если сработало ошибочно — кнопка «Это не отказ»).
- Храним только username, текст сообщения-лида и ссылку. Тексты не-лидов не сохраняются,
  участники чатов не выгружаются, телефоны не собираются. Лиды без активности 180 дней
  удаляются; `/forget @username` удаляет данные по запросу (GDPR), остаётся только хэш в стоп-листе.
- В Google Sheets уходят только ключевые поля, без текстов сообщений.

## Что проверить перед включением источников

- **Ключевые слова.** `config/keywords.yaml` — рабочий словарь. Фразы пишутся в обычной форме:
  окончания русских слов отрезаются автоматически. Корни из `stems_ru` срабатывают только
  вместе со словом из `stems_context`.
- **Telegram Ads Spy.** Адаптер читает `tgadsspy.com/api/v1/bots` и сам находит в ответе
  username, название и остальные поля; формат API стоит сверить на первом запуске (смотрите лог).
- **topapps.tg, Apps Center, FindMini.** Адаптер ищет на странице ссылки `t.me/...`. Если каталог
  рисуется скриптом, ссылок в HTML не будет — в логе появится предупреждение, тогда нужен
  их API или отдельный парсер. robots.txt соблюдается автоматически.
- **Фриланс-RSS.** Адреса лент в `settings.yaml` — примеры; проверьте условия площадок.
- **hh.ru** работает через официальный API.
- Модель по умолчанию — `claude-haiku-5-5` (уровень Haiku по ТЗ). Если точность на выборке
  ниже 80%, поставьте `llm.model: claude-sonnet-5-5` или поднимите `llm.effort`.
- База — SQLite (по ТЗ на старте). SQL простой, на PostgreSQL переносится заменой `db.py`.
