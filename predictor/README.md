# ⚽ footy — статистический анализатор футбольных матчей

Инструмент на Python, который разбирает матч (прежде всего **Лигу
Чемпионов**) как это делает опытный спортивный аналитик: оценивает силу
команд по статистике, строит вероятности **всех** основных рынков и ищет
ставки с **положительным матожиданием (value)** — там, где коэффициент
букмекера выгоден нам в долгую.

> ⚠️ **Честно и сразу.** Гарантированно выигрышных ставок не бывает. Модель
> даёт *вероятности*, а не точный исход. Смысл инструмента — не «угадать
> счёт», а находить ставки, где наша оценка вероятности выше той, что зашита
> в коэффициент. Это долгая игра на дисциплине и банкролл-менеджменте, а не
> способ «обыграть контору» за вечер. Ставь ответственно и только то, что не
> жалко потерять.

---

## Что считает

- **Исход 1X2** — победа хозяев / ничья / победа гостей, + двойной шанс.
- **Обе забьют (BTTS)** — да / нет.
- **Тоталы (Over/Under)** — 1.5, 2.5, 3.5 и любые линии, включая целые (с возвратом).
- **Азиатские форы** — целые, половинные и четвертные линии (с возвратом и разбиением ставки).
- **Точный счёт** — топ самых вероятных счетов.
- **Value + Келли** — при наличии коэффициентов: EV, честный кэф, перевес и рекомендуемая доля банка.
- **Экспрессы (аккумуляторы)** — сборка +EV-экспрессов из слейта/тура: value и надёжный варианты, Келли.

А также: **бэктест** стратегии на истории (ROI/yield), **калибровка** модели по
log-loss/Brier, **бленд с рынком** для точности, учёт **xG и травм**
(API-Football) и разбор **целого тура ЛЧ** с топом value-ставок.

## Как устроена модель

```
форма команд  ─►  ожидаемые голы (λ)  ─►  Пуассон + поправка Диксона–Коулза
                                               │
                                               ▼
                                        матрица счёта P[i][j]
                                               │
         ┌─────────────────────────────────────┼───────────────────────────┐
         ▼                 ▼                     ▼               ▼           ▼
       1X2              BTTS                 тоталы           форы      точный счёт
         └───────────────── сравнение с коэффициентами ─► поиск value (EV, Келли)
```

Что заложено «от аналитика»:

- **Вес свежести** — недавние матчи важнее (экспоненциальное затухание `decay`).
- **Дом / гости раздельно** — домашняя и выездная результативность считаются отдельно.
- **Регрессия к среднему (shrinkage)** — при малой выборке (а в ЛЧ её мало) сила
  команды подтягивается к среднему, чтобы не переобучаться на 2–3 матчах.
- **Диксон–Коулз** — поправка на то, что реальные матчи чаще заканчиваются
  ничьими низких счетов, чем предсказывает чистый Пуассон.
- **Контекстные поправки** — травмы лидеров, усталость, мотивация задаются
  ручными множителями `home_mult` / `away_mult`.

## Установка

```bash
cd predictor
pip install -r requirements.txt   # requests нужен только для режима fetch
```

Нужен Python 3.10+. Движок (всё, кроме `fetch`) работает без интернета и без
зависимостей.

## Быстрый старт

```bash
# Демо-матч (ничего настраивать не нужно):
python -m footy demo --bankroll 1000

# Разбор своего матча из JSON:
python -m footy predict examples/match_rma_mci.json --bankroll 1000

# Машинный вывод:
python -m footy --json demo
```

## Режим с реальными данными (API)

1. Получи ключ (бесплатный тариф football-data.org покрывает ЛЧ):
   https://www.football-data.org/
2. Скопируй `.env.example` в `.env` и впиши ключ:
   ```
   FOOTBALL_DATA_TOKEN=твой_ключ
   ```
   Файл `.env` в git не попадёт. **Ключ в чат/коммиты не вставляй.**
3. Запусти:
   ```bash
   python -m footy fetch --home "Real Madrid" --away "Man City" \
          --provider football-data --last 8 --bankroll 1000
   ```

Коэффициенты можно подать отдельным файлом, чтобы искать value:
```bash
python -m footy fetch --home "Real Madrid" --away "Man City" \
       --odds examples/odds.json
```

Поддерживается и **API-Football** (`--provider api-football`, ключ
`API_FOOTBALL_KEY`, у него есть xG и составы).

## Формат JSON-матча

Смотри `examples/match_rma_mci.json`. Коротко:

```jsonc
{
  "league": { "home_goals": 1.55, "away_goals": 1.25 },  // база лиги
  "context": {
    "decay": 0.85,        // вес свежести (0..1, больше = ровнее)
    "shrink_k": 3.0,      // сила регрессии к среднему
    "rho": -0.08,         // параметр Диксона–Коулза
    "home_mult": 1.0,     // поправка к голам хозяев (травмы/мотивация)
    "away_mult": 0.95
  },
  "home": { "name": "...", "matches": [ {"gf": 3, "ga": 1, "venue": "H"}, ... ] },
  "away": { "name": "...", "matches": [ ... ] },   // venue: "H" дома, "A" в гостях
  "odds": {                                         // опционально — для поиска value
    "1x2":    { "home": 2.05, "draw": 3.70, "away": 3.40 },
    "btts":   { "yes": 1.66, "no": 2.15 },
    "totals": { "2.5": { "over": 1.72, "under": 2.08 } },
    "ah":     [ { "line": -0.5, "home": 1.90, "away": 1.90 } ]
  }
}
```

`matches` — последние игры, **самый свежий первым**.

## Что показала проверка на реальных данных (октябрь 2026)

Walk-forward на football-data.co.uk: 8 лиг × 4–5 сезонов, ~11 000 матчей,
прогноз каждого матча — только по сыгранным до него.

| Лига | Модель «форма» | Модель «рейтинг» | Рынок (закрытие) |
|---|---|---|---|
| АПЛ | 1.024 | 0.989 | 0.965 |
| Ла Лига | 1.023 | 0.994 | 0.960 |
| Бундеслига | 1.022 | 1.006 | 0.971 |
| Серия А | 1.021 | 0.987 | 0.968 |
| Лига 1 | 1.020 | 1.000 | 0.977 |

(log-loss по 1X2, меньше — лучше; угадайка = 1.099.)

- **Рейтинг по всей истории** (затухание по времени, полураспад 365 дней,
  5 псевдо-матчей, приор «новичок лиги слабее среднего») заметно точнее модели
  «последние 10 матчей». Теперь это модель по умолчанию в `backtest`/`calibrate`,
  в вебе и в боте.
- **Тоталы откалиброваны**: прогноз доли ТБ2.5 совпадает с фактом с точностью 1–2%.
- **Рынок всё равно точнее**, и ставки на «value» по модели на истории дают
  ROI от −3% до −20% во всех лигах, в том числе по лучшему кэфу среди контор
  (`--odds-source max`) и при смешивании с рынком. Устойчивого перевеса нет.
  Используй модель как **оценку вероятностей**, а расхождение с линией — как
  повод разобраться (составы, мотивация), а не как готовую ставку.
- **Модель уступает рынку в различении команд, а не в калибровке**: где
  рынок видит фаворита на 80%, модель даёт ~79%, а побеждают в 88% случаев.
  Поэтому в вебе и боте **итог строится от линии**: подбираются ожидаемые голы,
  при которых матрица счёта повторяет честную линию (Pinnacle или среднее по
  конторам) по 1X2 и тоталам, и из неё считаются все рынки (точный счёт,
  «обе забьют», форы). Вес линии 0.9, модели 0.1 — так на истории точнее всего;
  чистая модель показывается отдельно как второе мнение.
- **Кэфы выше честной линии** (лучшая цена среди ~25 контор против Pinnacle
  по тому же исходу) на истории дают ≈ 0 ROI (от −7% до +4% по лигам). Это
  поиск ошибок в ценах, а не источник дохода. Выбросы (устаревшие цены дальше
  медианы на 15%+) отбрасываются.
- **ЛЧ**: межлиговая модель (сила страны по еврокубкам × рейтинг во внутренней
  лиге × результаты в ЛЧ) — log-loss 0.912 на 414 матчах ЛЧ 2024–2026.
  Без неё «Sabah — Дортмунд» выглядел почти равным матчем.

## xG, травмы и журнал прогнозов

- **xG (Understat, топ-5 лиг)** — рейтинг по xG смешивается с рейтингом по голам
  (70/30). Walk-forward 2023–2026, ~5500 матчей: log-loss 1X2 0.9873 → 0.9839,
  улучшение во всех пяти лигах. Скачивается сам, кэш в `hist/understat_*.json`.
- **Травмы (АПЛ, Fantasy Premier League API)** — список «кто не сыграет / под
  вопросом» в боте и вебе, и скромная поправка к атаке в модельной части
  (доля игрока в xG+xA команды × P(не сыграет) × 0.5, не ниже ×0.8). Это
  эвристика: архива травм нет, на истории не проверить. Для других лиг
  бесплатного источника нет (API-Football free не даёт текущий сезон).
- **xG и в ЛЧ**: приор команды в межлиговой модели берёт внутренний рейтинг
  со смесью xG (70%) — log-loss на 414 матчах ЛЧ 0.9129 → 0.9101.
- **ClubElo** (clubelo.com) — межлиговый Elo всех клубов как второе мнение
  (1X2 в боте/вебе и в журнале). Архива у сайта нет, на истории не проверить,
  поэтому в итоговый прогноз пока не входит: вес решим по журналу.
- **Журнал** (`python -m footy journal run|report`, бот: `/stats`) — снимки
  прогнозов и линии перед матчами ЛЧ и топ-5, затем счёт и закрывающая линия
  (для лиг — закрытие Pinnacle из CSV football-data.co.uk, для ЛЧ — снимок за
  ~1.5 ч до игры). Отчёт: точность итога/модели/линии/закрытия и **CLV**
  «кэфов выше честной линии». Это проверка перевеса на будущем, а не на
  истории. Лимит The Odds API (500/мес) расходуется ~6–12 кредитов в день.

## Что ещё проверено на истории (октябрь 2026)

- **Итог по 1X2 = чистая линия.** На 4380 матчах 2024–2026 любая примесь
  модели или Elo к закрывающей линии ухудшает log-loss (0.9679 → 0.9682+).
  Смесь «линия 90% + модель 10%» оставлена только для производных рынков
  («обе забьют», точный счёт), где она помогала.
- **Своё Elo** (K=20, дом. преимущество 60, поправка на разницу мячей) точнее
  нашей модели по голам (0.9896 vs 0.9933), а **модель + Elo пополам** — ещё
  лучше (0.9878). Поэтому без линии итог = модель + ClubElo 50/50.
- **Ничьи**: на 9700 матчах 8 лиг рынок оценивает их точно (28.9% vs 28.8% в
  равных матчах), ставка на ничью в равных матчах даёт −2.8% (маржа). Перекос
  в 2024–26 был шумом — поправок не вводим.
- **Отдых и плотный календарь** (лига + ЛЧ): закрывающая линия уже это
  учитывает, остатки в пределах шума — поправок не вводим.

## Где ставить, движение линии, проверка на наших матчах

- **Цены по конторам** (20–25 контор The Odds API) пишутся в журнал при каждом
  снимке. `/books` (CLI `journal books`): средняя цена конторы против честной
  линии в момент снимка и против закрывающей. В уведомлениях — «лучший кэф в X».
- **Движение линии**: если с раннего снимка матча (запрос `/today`, разбор
  матча в боте) честная вероятность исхода сдвинулась на ≥4 п.п., уведомление
  за час предупреждает и говорит, в пользу рекомендованной ставки это или против.
- **Проверка на наших матчах** (`/stats`, CLI `journal calibrate`): калибровка
  линии, лучший вес модели к линии (с 200+ матчей), ставки из уведомлений по
  уровню уверенности — заход, ROI и CLV (с 30+ ставок на уровень). Итоги ставок
  из уведомлений приходят утром вместе с остальными.

## Уведомления за час до матчей

Таймер `footy-alerts` (каждые 10 минут) присылает всем из `TELEGRAM_ALLOWED_IDS`
разбор матчей, которые начнутся в ближайший час (ЛЧ + топ-5, список —
`FOOTY_ALERT_COMPS`): линия, модель (рейтинг+xG), ClubElo; ✅ ставка, только если
лучший кэф выше честного (EV ≥ +1%), шанс ≥ 35% и модель/Elo не против; ⛔
«пропускаю», если перевеса нет; предупреждение, если модель расходится с линией
на ≥ 8 п.п. (линия знает про составы); самый вероятный исход; травмы (АПЛ);
проверенные каперы — как доп. мнение. Тот же снимок пишется в журнал — почти
закрывающая линия, бесплатно.

**«Обе забьют» с реальными кэфами** — в уведомлениях и в разборе матча в боте:
шанс по линии без маржи, лучший кэф и контора, EV, мнение модели. The Odds API
отдаёт этот рынок только по одному матчу (1 кредит за матч), поэтому в `/today`
его нет, а в уведомлениях он отключается при остатке < `FOOTY_BTTS_RESERVE`
(деф. 150).

Кредиты: ~2 за «волну» матчей турнира (≈70 в неделю) + 1 за «обе забьют»
каждого матча (≈40 в неделю) — ≈450 в месяц при всех уведомлениях. Защита: при
остатке < 150 — без «обе забьют», < `FOOTY_ODDS_RESERVE` (деф. 50) — без линии.
Проверка без отправки: `python -m footy alerts --dry-run`.

## Каперы: консенсус проверенных × линия (`/tips`)

Бот `/tips`, CLI `python -m footy tips`. Футбол и хоккей.

- **Источники**: BetBuddyRank (открытые JSON, каперы X, каждая ставка привязана
  к посту и счёту, удалённые посты остаются в статистике) — основной;
  nb-bet — второй голос: публично видны только лента (~15 прогнозов) и
  рейтинг за 30 дней, профили закрыты robots.txt, внутренний API не используем.
- **Фильтр** (`tipsters_config.json`, правится без кода): ≥60 рассчитанных и
  ≥40 ставок с кэфом в виде спорта; **ROI со сжатием к среднему** всех каперов
  (−3.5%, 200 псевдо-ставок) > 0; заход выше ожидаемого по кэфам (z ≥ 1);
  средний кэф 1.35–3.5; удалённых постов ≤10%; активен за 14 дней; без провала
  за 30 дней. Почему так строго: по данным BetBuddyRank успех каперов почти не
  повторяется (корреляция половин истории 0.04, топ ROI +8.8% → +1.2%), а из
  ~400 каперов «значимо в плюсе» ~20 оказались бы случайно. Сейчас проходят:
  футбол 10, хоккей 7.
- **Оценка**: вероятность — из честной линии (наш сервис для футбола; The Odds
  API h2h для NHL/SHL/Liiga/AHL; иначе кэфы каперов минус
  5% маржи); каперы сдвигают её максимум на 3 п.п. Уверенность 0–100: есть ли
  линия, сколько проверенных каперов согласны/против, согласны ли наша модель
  и Elo, EV по лучшему кэфу.
- **Лучшие кандидаты** — только уверенность ≥45 и цена не ниже честной
  (EV ≥ −1%). Пустой список — нормальный ответ. Итоги кандидатов на следующий
  день — по оценке BetBuddyRank.

## Утренняя рассылка и /today

Каждый день в 09:00 МСК бот присылает всем из `TELEGRAM_ALLOWED_IDS` **итоги
вчерашних ставок** (✅/❌ со счётом, результат по 1 ед.) — бесплатно, без
запросов линии. Ставки на день — **по запросу `/today`**: лучшие события (линия,
модель и ClubElo согласны, шанс ≥ 40%, лучший кэф не хуже честного) и три
экспресса (кэф ~2, ~3, ~5). Запрос `/today` заодно пишет журнал и подборку дня —
из уже скачанных кэфов, — по ним утром приходят итоги. Полный режим с линией
утром: `python -m footy digest --with-odds` (тратит кредиты).

## Экспрессы с максимальным шансом захода

Бот: `/express`, веб: кнопки «🎯 Экспресс», CLI: `python -m footy express [--target 3]`.

- **Самые надёжные** (на 2/3/4 события + альтернатива из других матчей): из
  каждого матча — один самый вероятный исход (фаворит, двойной шанс, тоталы,
  «обе забьют»), не дешевле 1.20.
- **Под кэф ~2 / ~3 / ~5**: точный подбор (рюкзак по log-кэфу) — экспресс с
  МАКСИМАЛЬНЫМ шансом захода при кэфе ≥ цели, лучший на 2..5 событий.
  Маржа есть в каждой ноге и в экспрессе умножается, поэтому при том же кэфе
  2–3 события с нормальной ценой заходят чаще, чем 6–8 «надёжных» по 1.15.
- Шанс — из честной линии без маржи (Pinnacle, где нет — среднее), для исходов
  вне линии — итоговая матрица. Цены — **средние по конторам**: экспресс
  ставится в одной конторе, лучшие цены разных контор в один купон не собрать.
  Двойной шанс считается из кэфов двух исходов; ТБ 1.5 и т.п. — оценка
  (справедливый минус ~6%).
- EV у всех вариантов отрицательный (примерно −7…−20%): это маржа. Бот
  показывает самые вероятные комбинации, а не «верняк».
- Пример (16.10.2026, 48 ч): кэф ≥3 — 2 события, заход 31%; кэф ≥5 — 2 события,
  заход 18.5%.

## Сервер

`./deploy/deploy.sh [ssh-хост]` (деф. `tgpanel-backup`): код в `/opt/footy/app`,
venv, systemd-сервисы `footy-bot`, `footy-web` (только localhost; открыть:

`footy-alerts` (каждые 10 минут — уведомления за час до матчей). Кредиты The Odds

50); кэш линии 30 минут, остаток — `/credits`.


Выбираешь турнир -> ближайшие матчи -> разбор: 1X2 (модель и рынок),
тоталы, «обе забьют», вероятные счета, расхождения с линией и вердикт. В боте
можно просто написать `Arsenal - Chelsea` или `Real Madrid - Barcelona PD`.
`TELEGRAM_ALLOWED_IDS` ограничивает круг пользователей бота.

Турниры: ЛЧ (CL), АПЛ (PL), Чемпионшип (ELC), Ла Лига (PD), Бундеслига
(BL1), Серия А (SA), Лига 1 (FL1), Эредивизи (DED), Примейра (PPL).

## Живые коэффициенты (The Odds API)

Ключ (бесплатно 500 кредитов в месяц): https://the-odds-api.com, затем
`ODDS_API_KEY=...` в `.env`. Один запрос линии турнира стоит 2 кредита.

```bash
python -m footy odds --competition PL                 # линия, лучший кэф
python -m footy odds --competition CL --mode pinnacle --save cl_odds.json
python -m footy round --competition CL --date-from 2026-10-20 \
       --date-to 2026-10-22 --live-odds --top 10
python -m footy fetch --home Arsenal --away Chelsea --competition PL --live-odds
```

`--mode`: `best` (лучший кэф среди контор), `avg`, или ключ конторы. Веб и бот
подхватывают кэфы сами, если ключ задан. Названия команд из разных
источников сопоставляются автоматически (`footy/teams.py`).

## Бэктест на истории

Проверяет, была ли стратегия прибыльной в прошлом — **без подглядывания в
будущее**: прогноз на каждый матч строится только по играм, сыгранным до него.

```bash
# Демо на синтетической «лиге» (идёт в комплекте):
python -m footy backtest examples/history_demo.json --min-ev 0.0 --min-matches 3

# Реальные данные — бесплатные CSV football-data.co.uk (python -m footy download).
# Несколько сезонов подряд — маской:
python -m footy backtest "hist/E0_*.csv" --min-ev 0.03 --stake kelly --bankroll 1000
python -m footy backtest "hist/E0_*.csv" --model form --odds-source max
```

Выводит: число ставок, оборот, прибыль, **ROI (yield)**, долю зашедших и
разбивку по рынкам. Параметры: `--min-ev` (порог value), `--min-matches`
(сколько истории нужно), `--form-window`, `--stake flat|kelly`, `--kelly-frac`,
`--model ratings|form`, `--odds-source b365|avg|max|pinnacle`, `--blend W`
(вес рынка при отборе ставок). Выводит и точность модели против рынка.

> Если на истории минус — это честный сигнал: по этим данным и порогу играть
> не стоит. Так и должен работать настоящий бэктест.

## xG, составы и травмы (API-Football)

При провайдере `api-football` можно подтянуть **xG** (точнее голов отражает
силу) и учесть **травмы** автоматически:

```bash
python -m footy fetch --home "Real Madrid" --away "Man City" \
       --provider api-football --season 2024 --with-xg --injuries
```

- `--with-xg` — модель считает силу по ожидаемым голам, а не по фактическим
  (по 1 запросу на матч — расходует лимит).
- `--injuries` — число недоступных игроков снижает атаку команды (скромная
  настраиваемая поправка, т.к. данные не говорят, насколько важен игрок).

## Анализ целого тура ЛЧ

Разбирает все матчи тура разом и выдаёт **топ value-ставок по туру**:

```bash
# Сводка по туру (вероятности по каждому матчу):
python -m footy round --matchday 6 --provider football-data

# С коэффициентами — топ value-ставок тура, отсортированных по EV:
python -m footy round --matchday 6 --odds examples/round_odds.json \
       --top 10 --bankroll 1000
```

Файл коэффициентов — JSON с ключами вида `"Real Madrid vs Man City"`:

```json
{
  "Real Madrid vs Man City": { "1x2": {"home": 2.05, "draw": 3.7, "away": 3.4} },
  "Bayern vs PSG":           { "btts": {"yes": 1.7, "no": 2.1} }
}
```

Можно задать диапазон дат вместо тура: `--date-from 2026-01-20 --date-to
2026-01-22`, и отфильтровать по статусу: `--status SCHEDULED,TIMED`.

## Точность: бленд с рынком и калибровка

Две честные вещи, которые реально повышают и **измеряют** точность.

**1. Бленд с рынком (`--blend`).** Коэффициенты букмекера без маржи — сильнейший
публичный прогноз. Флаг `--blend W` (вес рынка `W` в `[0,1]`) показывает колонку
«модель / рынок / бленд» по 1X2 и даёт самую точную точечную оценку вероятности.
Поиск **value при этом всегда идёт по чистой модели** (подмешать рынок = убить
перевес по определению). Флаг работает и до, и после подкоманды:

```bash
python -m footy demo --blend 0.4
python -m footy --blend 0.4 predict examples/match_rma_mci.json
```

**2. Калибровка по истории (`calibrate`).** Walk-forward перебор параметров
модели (`rho / decay / shrink_k`) с отбором по строгой метрике точности —
**log-loss** (или `--metric brier`). Без подглядывания в будущее: прогноз на
каждый матч строится только по сыгранным ранее.

```bash
python -m footy calibrate examples/history_demo.json --min-matches 3
# или на реальных CSV с football-data.co.uk:
python -m footy calibrate "hist/E0_*.csv"               # рейтинговая модель
python -m footy calibrate "hist/E0_*.csv" --model form  # модель формы
```

Выдаёт лучшие наборы параметров (ориентир: случайная угадайка 1X2 даёт
log-loss ≈ 1.0986 — модель должна быть ниже). Найденные `rho/decay/shrink_k`
подставляй в `context` матч-файла — или сохрани их в **профиль** и они будут
подхватываться автоматически:

```bash
python -m footy calibrate E0.csv --save          # -> .footy_profile.json
python -m footy predict match.json               # профиль применится сам
python -m footy predict match.json --no-profile  # игнорировать профиль
```

Профиль не перетирает параметры, заданные тобой явно, — только дефолтные.

**3. Приор силы команды (`rate` + `--ratings`).** Главная причина ошибок модели
«только форма» — тонкая выборка (сильный клуб с парой неудач получает заниженную
силу). Лиговый рейтинг атаки/обороны по БОЛЬШОЙ истории служит приором:

```bash
python -m footy rate E0.csv                       # таблица сил команд
python -m footy predict match.json --ratings E0.csv --prior-weight 0.5
python -m footy fetch --home "Arsenal" --away "Chelsea" --ratings E0.csv
```

λ матча смешивается как `(1−w)·форма + w·приор`. Команды не из истории получают
среднюю силу лиги (помечается в выводе). Имена команд должны совпадать с историей.

**4. CLV в бэктесте.** Если в данных есть закрывающие кэфы (CSV football-data.co.uk
со столбцами `B365CH/CD/CA` и т.п., или поле `closing` в JSON), бэктест считает
**CLV** по ставкам 1X2 — обыгрывали ли мы закрывающую линию. Это лучший
долгосрочный индикатор реального перевеса, даже когда выборка по прибыли шумная.

## Экспрессы (аккумуляторы)

Собирает экспрессы из слейта матчей: берёт **только +EV-ноги**, оставляет **по
одной ноге на матч** (чтобы не множить коррелированные исходы), и строит
экспрессы разной длины. Под независимостью матчей максимум EV при `k` ногах —
это top-`k` ног по EV, движок это и собирает.

```bash
# Оффлайн по слейту матчей с коэффициентами:
python -m footy acca examples/acca_slate.json --bankroll 1000 --blend 0.4

# Прямо из разбора тура ЛЧ (топ value-ставок -> экспрессы):
python -m footy round --matchday 6 --odds examples/round_odds.json --acca
```

Выдаёт **value-экспресс** (макс. EV), короткие варианты и **надёжный экспресс**
(самые вероятные ноги до целевого кэфа `--safe-odds`). Для каждого — итоговый
кэф, вероятность прохода, честный кэф, EV и доля банка по Келли. `--blend`
сближает вероятность прохода с рынком, чтобы не переоценивать шансы.

**Экспрессы по вероятности захода (`--by-prob` / `--acca-prob`).** Если нужны не
value, а просто **самые надёжные** экспрессы — этот режим **не требует
коэффициентов**: по каждому матчу берётся один самый вероятный исход из
безопасного меню (двойной шанс, тотал 1.5 больше / 3.5 меньше, BTTS-нет), и
строятся экспрессы с максимальной совместной вероятностью. Кэфы показываются
справедливые (1/P) — подставь реальные от своей конторы.

```bash
python -m footy acca examples/acca_slate.json --by-prob --min-prob 0.6
# на живом туре ЛЧ (нужен только FOOTBALL_DATA_TOKEN, коэффициенты не нужны):
python -m footy round --date-from 2026-10-20 --date-to 2026-10-22 \
       --status SCHEDULED,TIMED --acca-prob --min-prob 0.6
```

> Высокий шанс захода = низкий кэф и, как правило, **−EV**. Это осознанный
> выбор «надёжность вместо выгоды», движок про это честно предупреждает.

> Экспресс множит кэф, маржу **и** дисперсию. Одиночные +EV-ставки почти всегда
> выгоднее в долгую — движок это честно напоминает.

Формат слейта — список матчей (как `predict`-файл) в одном JSON:
`{"matches": [ {league, context, home, away, odds}, ... ]}`.
Пример — `examples/acca_slate.json`.

## Экспресс внутри матча (SGP, с учётом корреляции)

Исходы одного матча **нельзя** перемножать как независимые: «П1» и «тотал
больше» коррелируют. `sgp` считает совместную вероятность прямо из матрицы
счёта и показывает коэффициент корреляции (joint / naive):

```bash
python -m footy sgp examples/match_rma_mci.json \
       --pick 1 --pick "over 2.5" --odds 2.6 --bankroll 1000
```

Поддержка выборов: `1/x/2`, `1x/12/x2`, `btts`/`btts_no`, `"over 2.5"`,
`"under 3.5"` (EN/RU). С `--odds` считает EV и Келли. Букмекеры режут кэф SGP
именно из-за корреляции — движок показывает справедливый кэф для сверки.

## Кэш и лимиты API

Провайдеры кэшируют ответы на диск и переживают лимиты (429/5xx) ретраями с
бэкоффом (учитывают `Retry-After`). Управление через окружение: `FOOTY_CACHE_DIR`
(деф. `.footy_cache`), `FOOTY_CACHE_TTL` (сек, деф. 6 ч), `FOOTY_NO_CACHE=1`.
